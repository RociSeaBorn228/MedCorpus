## Аккаунты и панель разработчика

- Вход — на странице `login.html`. Самостоятельной регистрации нет: аккаунты создаёт разработчик в `admin.html`.
- Личный кабинет — `account.html`: профиль, смена собственного фото, должности, ранг, клан, статус, выговоры и личные рапорта.
- Панель разработчика — `admin.html`: создание аккаунтов (имя, email, пароль), редактирование и удаление пользователей, должности, ранги, кланы, статусы, фото, устные (3) и письменные (2) выговоры, модерация рапортов.
- Раздел «Состав» — отдельная страница `sostav.html`: руководство, основной состав, а также отдельные таблицы владельцев техники Скальпеля и владеющих медицинским Тайдзюцу (по 10 мест с вакансиями). Разработчик может открыть карточку участника и сразу изменить данные или выговоры, а также удалить аккаунт.
- Должность «Глава Медицинского Корпуса» автоматически показывает участника в блоке «Руководство». Если снять должность, он возвращается в основной состав.
- Любой аккаунт, созданный разработчиком, сразу попадает в «Основной состав» с должностью «Интерн» — вручную добавлять его не нужно и публиковать ничего не требуется. При включённой общей базе он появляется в составе у всех устройств.

### Создание аккаунтов

Регистрация закрыта. Чтобы выдать доступ:

1. Войдите как разработчик и откройте `admin.html`.
2. В блоке пользователей нажмите **«Создать пользователя»**.
3. Укажите имя, email и пароль (минимум 6 символов), заполните должность, ранг и остальные поля.
4. Сохраните — аккаунт сразу появится в составе и синхронизируется с другими устройствами.

Пароль хранится только как SHA-256-хэш: посмотреть его нельзя, можно лишь задать новый в той же форме. Сообщите участнику email и пароль лично.

### Общая база (Supabase)

Сайт остаётся статическим, но данные можно синхронизировать между всеми браузерами и устройствами через Supabase.

1. Создайте проект на [supabase.com](https://supabase.com) (бесплатного тарифа достаточно).
2. Откройте **SQL Editor** и выполните скрипт `supabase/schema.sql` — он создаёт таблицу `medcorpus_state` и правила доступа.
3. Откройте **Project Settings → API** и скопируйте:
   - **Project URL** (вида `https://xxxx.supabase.co`);
   - ключ **publishable** (строка `sb_publishable_…`) либо legacy **anon public** (`eyJ…`).
4. Вставьте значения в `js/config.js`:

```js
window.MC_CONFIG = {
  supabaseUrl: "https://xxxx.supabase.co",
  supabaseKey: "sb_publishable_…",
  table: "medcorpus_state",
  rowId: "main"
};
```

5. Откройте сайт в том браузере, где состав заполнен правильно, зайдите в **Панель разработчика → Общая база** и нажмите **«Опубликовать данные этого браузера»**. Это один раз задаёт общее состояние; дальше всё синхронизируется само.

После этого состав, аккаунты, должности, выговоры и рапорта хранятся в общей таблице: изменения из панели разработчика появляются у всех посетителей в течение ~15 секунд, а новая вкладка/браузер сразу получает актуальные данные.

Состояния сливаются по каждой записи отдельно (у участника и рапорта свой `updatedAt`, удаления помечаются «надгробиями»). Поэтому созданный аккаунт или правка, сделанная на одном устройстве, не пропадает, даже если другое устройство в этот момент сохраняет своё состояние. Кнопка **«Опубликовать данные этого браузера»** работает иначе: она делает состояние этого браузера общим и заменяет им данные остальных устройств.

Если `supabaseUrl` и `supabaseKey` пустые, сайт работает как раньше — на локальном `localStorage`.

> Ключ `publishable` (или `anon`) публичный по назначению, но правила из `schema.sql` разрешают любому посетителю перезаписывать общее состояние. Для закрытой базы с настоящей авторизацией нужен Supabase Auth и отдельные правила RLS. Не используйте на этом сайте реальные пароли от других сервисов.

### Важно: без Supabase данные хранятся в браузере

GitHub Pages — это статический хостинг без сервера и базы данных. Пока `js/config.js` не заполнен:

- аккаунты, сессия, состав и рапорта хранятся в `localStorage` **конкретного браузера**;
- созданные аккаунты и изменения не видны другим посетителям;
- после очистки данных браузера локальные аккаунты и правки пропадут.

## Как опубликовать на GitHub Pages

### Через браузер

1. Создайте публичный репозиторий `MedCorpus`.
2. Загрузите все файлы проекта, включая папки `css`, `js`, `images` и файл `.nojekyll`.
3. Откройте **Settings → Pages**.
4. **Source**: `Deploy from a branch`; **Branch**: `main`, папка `/ (root)`; **Save**.
5. Через 1–3 минуты сайт будет доступен по адресу `https://ВАШ-ЛОГИН.github.io/MedCorpus/`.

### Через GitHub CLI без установленного Git

```powershell
gh repo create MedCorpus --public
gh api --method PUT "repos/ВАШ-ЛОГИН/MedCorpus/contents/index.html" -f message="Upload" -f content="$(base64 index.html)"
```

Для массовой загрузки удобнее использовать GitHub Contents API или установить Git. В этом проекте сайт уже опубликован в `RociSeaBorn228/MedCorpus`.

## Как обновлять сайт

- Через браузер: откройте файл в репозитории → карандаш **Edit** → **Commit changes**.
- Через Git: измените файлы, затем `git add . && git commit -m "правки" && git push`.
- GitHub Pages пересобирается автоматически за ~1 минуту. Обновляйте страницу с `Ctrl + F5`.

## Оформление

- Тёмная тема: фон `#0d0d0d`, карточки `#151515`, акцент `#388e3c`.
- Цвета, шрифты и отступы — в начале `css/style.css`, блоки `:root` и `[data-theme="light"]`.
- Главный акцент — переменная `--accent`.
- Светлая/тёмная тема переключается кнопкой в шапке, выбор запоминается в браузере.
- Тексты страниц лежат прямо в HTML — ищите нужный абзац по словам.

## Важные мелочи

- Все ссылки относительные, поэтому сайт работает и в подпапке GitHub Pages.
- Не переименовывайте `index.html` — это точка входа.
- GitHub различает регистр букв: `Images/Logo.svg` и `images/logo.svg` — разные пути.
- Файл `.nojekyll` отключает обработку Jekyll.
- `404.html` GitHub Pages показывает автоматически при переходе на несуществующий адрес.
- Фото участников: прямая ссылка на картинку (`https?://…/photo.jpg`) или ссылка на пост/галерею Imgur (например, `https://imgur.com/gallery/...`). Ссылки Imgur при сохранении превращаются в прямую ссылку на изображение; неподходящие адреса отклоняются с понятной ошибкой. Пользовательский текст экранируется.
